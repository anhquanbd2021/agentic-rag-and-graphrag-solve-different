Strategy guide

One lab, three architectures

The lab proves a simple claim: agentic RAG pays at query time, GraphRAG pays up front, and a hybrid can use both when the question needs a path.

Read the trace. Every control exposes the same deterministic support-knowledge-base model.

Start here

What this demo proves

Set the agent budget to 1 and GraphRAG coverage to 60%. The EU checkout question fails in two different ways: the agent runs out of search rounds, while the graph is missing the payment-decision edge. Raise both controls and the same question becomes supported without changing the workload.

Feature 01

Agent budget

The control loop plans retrieval, searches, and reflects before answering. It is flexible, but every extra round is paid at question time.

Prebuilt index

GraphRAG: extract, summarize, traverse

Feature 03

Graph coverage

Coverage models what the ingestion pipeline extracted. A low-coverage graph can still answer lookup questions while missing the edge that connects the incident.

Proves
GraphRAG’s up-front bill does not guarantee complete evidence.
Key detail
the missing edge names appear in the trace, not just no answer.
Feature 04

Cost model

Build calls are separate from per-query calls. That separation makes the pay once or pay every question trade-off inspectable.

Proves
a graph has a build cost even when traversal calls are cheap.
Key detail
the 30-query total shows when up-front work pays back.

Combination

Hybrid: let the agent decide the path

Feature 05

Agent-on-graph

The hybrid first reads the graph path, then fills missing evidence with a fallback search. The agent owns the control decision; the graph supplies reusable structure.

Proves
the strongest system can combine an index with a query-time loop.
Key detail
with a tiny budget, the fallback can still fail — combination is not magic.
Feature 06

Failure reproducibility

The failure is deterministic: same strategy, budget, coverage, and question always produce the same trace and call count.

Proves
the lab is a testable model, not a canned screenshot.
Key detail
unit tests assert the pass and fail paths directly.
